SC Launcher · 다음 게임 자동 재연결 수정 (2026-10-07)
빌드: game-session-reconnect-fix-20261007
실행 파일: 이 폴더의 SC-Launcher.exe
대상: StarCraft 1.23.10.13515 x64

한 판을 끝내고 같은 스타에서 다음 판으로 들어갔을 때 다중 제어와 컴퓨터
동맹 기능이 꺼지는 문제에 대한 수정본입니다. 게임 사이의 연결 대기를 영구
실패로 바꾸던 경로를 고치고 게임마다 입력 담당 정보와 임시 상태를 정리합니다.
실게임 두 판을 연속 실행한 검증은 아직 없습니다.

사용 확인
1. 새 모듈을 적용하기 위해 이번에는 스타와 기존 런처를 완전히 종료합니다.
   이 폴더의 SC-Launcher.exe를 실행하고 스타에 연결합니다.
2. 첫 게임에서 본인의 같은 종류 유닛을 선택하고 백틱(`)으로 다중 제어합니다.
   컴퓨터가 있으면 동맹 버튼과 컴퓨터 체크 → 확인도 확인합니다.
3. 게임을 끝내고 스타와 런처를 종료하지 않은 채 두 번째 게임에 들어갑니다.
   유닛을 새로 선택하고 백틱을 새로 누릅니다. 게임 사이에 '게임 연결'을
   다시 누르는 절차는 필요하지 않습니다. 이전 그룹은 다음 판에 가져오지 않습니다.
4. 두 번째 게임에서 이동/정지/공격, 생산/랠리, 동맹 버튼, 컴퓨터 체크 →
   확인 후 관계 유지를 확인합니다. 세 번째 게임도 같은 방식으로 확인합니다.

연결 위치가 준비되지 않으면 대기하고 확인된 원래 연결 위치가 다시 준비되면
재연결합니다. 실제 연결 오류나 검증되지 않은 다른 연결 코드는 계속 구분합니다.
다른 사람 또는 컴퓨터가 남아 있으면 동맹 버튼 표시를 갱신하고 모두 없으면
숨기는 기존 조건을 유지합니다. 사라진 버튼의 실게임 해결 확인은 아직 없습니다.

컴퓨터 체크는 내 플레이어 → 해당 컴퓨터의 관계만 바꿉니다.
컴퓨터 쪽의 관계는 변경하지 않습니다. 체크는 즉시 적용을 요청하고 기존 확인
버튼이 컴퓨터 값을 되돌리지 않도록 원래 출력에 반영하는 직전 수정도 포함합니다.
취소/Esc는 이미 보낸 변경을 되돌리지 않습니다. 맵 트리거로 관계가 바뀌어도
오래된 값을 강제로 반복 전송하지 않습니다.

검증: native 361개 + managed 374개 = 총 735개 통과.
전체 C# 컴파일과 native DLL 릴리스 빌드 통과. 설치 원본 3개 읽기 해시 일치.
자체 데이터·메모리·파일 검사이며 실게임 검증은 포함하지 않습니다.
원본 설치 파일을 수정하지 않았고 기존 배포본도 보존했습니다.
상세 검증은 TEST-REPORT.md와 verification 폴더를 확인합니다.

문제가 재현되면 %LOCALAPPDATA%\SCMultiTest의 현재 PID 기록을 확인합니다.
mc-숫자-game-sessions.tsv: 게임·대기·재연결·입력 담당 유무·오류 전환
mc-숫자-callback-init.txt / init-error.txt: 마지막 연결 상태와 실제 오류
mc-숫자-alliance-transitions.tsv: 동맹창·컴퓨터·버튼 상태 전환
mc-숫자-alliance-output-log.tsv: 확인 출력 보완 및 거절 이유
mc-숫자-alliance-apply-log.tsv: 요청·전송·실제 반영·확인 처리

새 게임 전환 기록은 최근 64개 전환만 보관합니다. 같은 상태는 한 행으로
합치고 게임 종료 후에도 앞선 기록을 보존합니다. 주소·참가자 이름·실행 코드·
명령 내용은 담지 않습니다.
